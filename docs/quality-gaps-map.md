## 2) خريطة الأولويات (موجات)

نفّذي **موجة واحدة** ثم بوابة اختبار يدوي قصيرة، لا تخلطي الموجات.

```
موجة A — أمن سريع
    → موجة B — صلاحيات وجلسة
        → موجة C — فهارس + تقويم بنافذة تاريخ + ترقيم
            → موجة D — معاملات سلامة بيانات + تنظيف كود
                → موجة E — إنتاج (rate-limit · headers · seed)
```

---

## 3) موجة A — أمن سريع (حرج)

| # | المشكلة | أين تنظرين | المطلوب باختصار |
|---|---------|------------|-----------------|
| A1 | رفع SVG → XSS محتمل | `gallery/actions.ts` | امنعي `svg`؛ صور نقطية فقط + فحص نوع الملف |
| A2 | روابط `javascript:` في معرض/سوشيال | `gallery/actions.ts` · `settings` · `SiteFooter` | اقبلى `https:` فقط (واختياري http) |
| A3 | كلمة seed معروفة | `prisma/seed.ts` · `dev-credentials.md` | لا تشغّلي seed على إنتاج؛ غيّري كلمة الأدمن على أي سيرفر مشترك |

**اختبار يدوي موجة A:** حاولِ رفع SVG → مرفوض · رابط `javascript:alert(1)` → مرفوض · صفحة portfolio/footer آمنة.

> **حالة موجة A (2026-08-16):** أُغلقت بعد اختبار نهلة اليدوي — انظر [wave-a-completion.md](./wave-a-completion.md). التالي: موجة B.

## 4) موجة B — صلاحيات وجلسة (حرج/عالي)

| # | المشكلة | أين تنظرين | المطلوب باختصار |
|---|---------|------------|-----------------|
| B1 | أي موظف = أدمن كامل (لا RBAC) | `middleware.ts` · `session-token.ts` · كل `actions.ts` | دور في الجلسة + `requireAdmin()` / صلاحيات حسب الشاشة |
| B2 | المستخدم المعطّل تبقى جلسته حتى 7 أيام | `lib/auth.ts` · `getSession` | عند كل طلب: تحقق `User.active` من DB (أو نسخة جلسة/tokenVersion) |
| B3 | Server Actions بلا فحص جلسة داخلي | معظم `app/admin/(panel)/**/actions.ts` | أول سطر: `await requireSession()` — لا تعتمدين على middleware وحده |
| B4 | `/api/admin/*` خارج matcher الـ middleware | `middleware.ts` | أضيفي `/api/admin/:path*` **مع** الإبقاء على فحص الجلسة داخل الـ route |
| B5 | إنشاء موظفين/تغيير كلمات مرور بلا قيد دور | `employees/actions.ts` | مدير فقط يرفع صلاحيات ويعيد تعيين كلمات المرور |

**اختبار يدوي موجة B:** حساب غير مدير لا يدخل إعدادات/موظفين · تعطيل مستخدم يقطع الوصول فوراً · طلب API بدون كوكي = 401.

## 5) موجة C — توسّع وأداء (حرج عند نمو البيانات)

| # | المشكلة | أين تنظرين | المطلوب باختصار |
|---|---------|------------|-----------------|
| C1 | لا فهارس ثانوية تقريباً | `prisma/schema.prisma` | فهارس: `EventService.startsAt` · `eventId` · `Event.customerId` · `Payment.eventId` · `Customer.phone` · حالات الحجز… |
| C2 | التقويم يجلب **كل** EventService | `lib/calendar-events.ts` · API التقويم | فلتر `start`/`end` من FullCalendar فقط |
| C3 | قوائم بلا ترقيم | customers / events / payments / bookings / reports | `take`/`skip` أو cursor + بحث |
| C4 | تقارير CSV بلا حد | `lib/reports.ts` | نطاق تاريخ + حد أقصى للصفوف |

**اختبار يدوي موجة C:** تقويم شهر واحد سريع · قائمة زبائن بصفحة 20 · تصدير تقرير بمدى تاريخ محدود.
