## أسلوب «من يدخل؟»

دور ثابت بالاسم: **`مدير الأستوديو`** (`MANAGER_ROLE_NAME` في `lib/roles.ts`).  
لا حقل `canLogin` منفصل — دخول اللوحة = نفس شرط المسؤول.

## ما تغيّر

| بند | التنفيذ |
|-----|---------|
| 15.0 | `loginWithCredentials` يرفض غير المسؤول: «الدخول مسموح لحساب المسؤول فقط.» |
| 15.1 | جلسة غير مسؤول تُمسح · middleware يحوّل للّوجين · API أدمن 403 |
| 15.2 | `getVerifiedSession` يفحص `User.active` + الدور |
| 15.3 | Server Actions تبقى خلف `requireManager` |
| 15.4 | `/api/admin/*` بدون جلسة = 401 · غير مسؤول = 403 |
| 15.5 | طاقم: `passwordHash` اختياري (null) · النموذج يخفي كلمة المرور |
| مناسباتي | رابط السايدبار للمسؤول فقط (الطاقم لا يدخل أصلاً) |

حساب تجريبي مصور `photographer@alray.studio` **بلا دخول** (للتعيين على المواعيد بعد `db:seed`).

## اختبار يدوي (L1–L5 + بوابة 15)

1. **L1 / 15.0** دخول `admin@alray.studio` ينجح
2. **L2** محاولة `photographer@alray.studio` (حتى بكلمة قديمة إن وُجدت) → رفض واضح
3. **L3 / 15.5** إضافة مصور بدون كلمة مرور → يظهر في القائمة
4. **L4** تعيينه على موعد من تفاصيل المناسبة → يظهر على التقويم
5. **L5** لا مسار يفتح لوحة لغير مسؤول
6. **15.2** تعطيل حساب المسؤول → الطلب التالي يخرج من اللوحة
7. **15.4** `/api/admin/calendar/events` بدون تسجيل → 401

بعد **نجحت**: `pm-notify` gate 15 + رفع.
