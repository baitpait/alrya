# إجراءات صفوف الأدمن — أيقونات مناسبة للمصطلح

> قرار مدير المشروع: مصطفى البستنجي — **2026-08-17**  
> المكوّنات: `AdminActionIcons` · `ConfirmDelete` · `AdminBackLink`  
> الأنماط: `admin-shell.css`

---

## قاعدة ذهبية

**الأيقونة يجب أن تطابق معنى المصطلح.**  
لا تستخدمي «عين» لفتح التقويم، ولا كلمة «حذف» كنص زر في الجداول.

| المصطلح / الإجراء | `kind` / مكوّن | الشكل |
|-------------------|----------------|--------|
| عرض / تفاصيل عامة | `view` | عين |
| تعديل | `edit` | قلم |
| فتح ملف/كيان عام | `open` | مجلد |
| **فتح التقويم** | `calendar` | تقويم |
| **فتح المناسبة** | `event` | تقويم + علامة صح |
| **التقارير** | `reports` | أعمدة رسم |
| **حذف / إزالة** | `ConfirmDelete` | **سلة** |

---

## 1) روابط الرجوع — أزرار

```tsx
<AdminBackLink href="/admin/messages" label="رجوع للرسائل" />
```

ممنوع: `<Link className="text-link">← رجوع…</Link>`

---

## 2) الحذف — أيقونة سلة في كل الجداول والتفاصيل

**ممنوع:**

```tsx
<button type="submit" className="btn-danger">حذف</button>
<button type="submit" className="btn-danger">حذف المناسبة</button>
```

**مطلوب:**

```tsx
<ConfirmDelete
  action={deletePayment}
  id={p.id}
  fieldName="recordId"
  hiddenFields={{ eventId }}
  label={`حذف دفعة ${amount}`}
/>
```

يشمل: دفعات · خصومات · مواعيد المناسبة · إزالة طاقم · حذف المناسبة · زبائن · موظفين · عروض · رسائل · معرض · FAQ.

- تأكيد قبل الحذف إلزامي.
- `fieldName="recordId"` — **ممنوع** `name="id"` (يظهر في الفحص كـ `form#[object HTMLInputElement]`).

استثناء نادر: «رفض الطلب» في الحجوزات (ليس حذف صف جدول) — يجوز زر نصّي.

---

## 3) لوحة التحكم

| قبل | بعد |
|-----|-----|
| «فتح التقويم» | `kind="calendar"` |
| «المناسبة» | `kind="event"` |
| «التقارير» | `kind="reports"` |

---

## 4) اختبار يدوي

1. مناسبة تفصيل: لا كلمة «حذف» في الجداول — سلة فقط + تأكيد.  
2. حذف المناسبة = سلة + رسالة تأكيد قوية.  
3. لوحة التحكم: أيقونات تقويم/مناسبة/تقارير.
